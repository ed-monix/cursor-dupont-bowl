## Blockers

1. **Contract drift: faab.py's transaction entries violate `docs/schemas/transaction-entry.json`.**
   `scripts/faab.py:293-295` writes `"action": "faab_add"` and
   `"players": {"add": id, "drop": id|null}` (an object). The schema
   (`docs/schemas/transaction-entry.json:24-38`) requires `action` ∈
   `["add", "drop", "waiver_claim", "trade"]` and `players` as an **array of
   strings**. Two APPROVED tasks (2.1 and 2.4) ship mutually incompatible
   definitions of the league's permanent record; each task's tests validate its
   own shape and nothing cross-checks. Every real Saturday run will write
   log lines that fail the league's own schema. Human decision needed on which
   shape is canonical; the loser gets a one-file fix.

2. **Contract drift: `config/roster.json` and the validator's `roster_config` don't speak the same language.**
   `config/roster.json` is `{roster_positions: [...], settings: {...}}` (what
   sync_sleeper writes, `scripts/sync_sleeper.py:51,68-74`). But
   `lib/rosters.py:75-94` expects `{starters: {slot: [pos]}, bench_slots,
   ir_slots}` and there is **no adapter anywhere** (verified by grep: nothing
   outside sync_sleeper touches `roster_positions`). So
   `faab.py --roster-config config/roster.json` — the invocation faab.py's own
   docstring recommends (`scripts/faab.py:86`) — silently falls through to the
   hardcoded defaults. Harmless today only because the active config happens to
   equal the defaults; a synced custom league would be silently ignored.

3. **Reconciliation has no data source.** `/recap` step 2 (`.claude/commands/recap.md:24-30`)
   reconciles "the scoreboard's last live per-player scores" against finals —
   but `scripts/scoreboard.py` keeps live scores only in an in-memory cache
   (`scripts/scoreboard.py:512-528`) and never writes a snapshot to disk. The
   4.2 pipeline is a tested function with a permanently empty input; the recap
   step will no-op every single week.

4. **Undeclared state files.** CLAUDE.md build-mode rule: never invent state
   files without adding them to PLAN.md §8. Invented and not in §8:
   `state/weeks/*/faab-report.json` (saturday.md:75), `state/weeks/*/lineups.json`
   (sunday.md:62), `state/draft-grades.md` (draft.md:63). Also referenced
   elsewhere in PLAN but absent from the §8 contract list itself:
   `state/schedule.json`, `state/standings.json`, `state/draft-log.jsonl`,
   `state/rulings.md`, `state/weeks/*/{projections,stats,matchups,recap}`.
   §8 needs one consolidating edit (human decision, Opus session per ROUTING).

## Assessment: GM sophistication (will the personalities actually show?)

The **scaffolding is genuinely good** — better than the usual "give the agent a
persona paragraph" approach:

- The template's core rule (`teams/_template/general-manager.md:7-10`) — *every
  trait must cash out in a mechanical bias or it converges to "start the highest
  projection"* — is exactly the right defense, and the Reaction-to-Ownership
  section demanding mechanics ("must make a move you can describe as 'sending a
  message'") is where the chaos will come from.
- Personality has real surfaces: draft-pick one-liners printed live, Saturday
  `note_reply` + reasoning quoted verbatim, Sunday justification paragraphs,
  the Hall of Shame, draft grades "guaranteed to be unfair," and a commissioner
  voice that is already the best-written thing in the repo.
- The loop is right: recap → owner notes → GM reaction → recap. That's the
  engine of an ongoing show rather than 17 disconnected weeks.

Four gaps will mute the personalities as currently built:

1. **It's 100% scaffolding, 0% cast.** Zero GM files exist. Everything above is
   a stage with no actors; Phase 5 is now the critical path for the product.
2. **Sunday is context-starved.** The lineup run hands the agent only GM file +
   roster + players + opponent — no owner note, no standings, no last box
   score, no recap. With nothing to react to, every GM's Sunday collapses
   toward the projection column, and Sunday is the run people watch. Feed it
   this week's note, its own Saturday note_reply, and last week's result.
3. **No memory, so no grudges.** Agents never see their own past decisions,
   past note replies, or the recap that mocked them. Feuds and running bits —
   the best content — can't compound. The `press/` folder is in PLAN §3 and no
   command ever writes or reads it. Cheap fix: include the team's own
   `notes/` thread and its last N transactions (with reasoning) in every
   Saturday context.
4. **Trades can't work as specced.** Saturday's context gives a GM *no other
   team's roster*, so it literally cannot name players to ask for in
   `trade_offer.in` — offers will be blind guesses or invalid ids. Rosters
   aren't secret (only GM files are); publish a league-wide roster board into
   the Saturday context. Until then the single highest-chaos mechanic is
   decorative.

One more nudge: since free agents arrive as `{name, pos, team, proj_pts}`,
write GM biases against fields that exist — team allegiance, position mania,
injury superstition, name-based spite — not age/college/contract lore the
agent can't see. And put PLAN §10's "most in-character move of the week" award
into the recap: it's the incentive that keeps ten agents from converging into
one.

## Implementation recommendations — GM sophistication

Concrete build-out for the four gaps above, sized as tickets. Everything here
reuses data the repo already syncs — no new endpoints, no new deps. Items
marked **§8** add or change a data contract and therefore need the human +
Opus-session path per ROUTING before any dispatch.

### R1. GM memory: the dossier + press file (the priority item)

Give every GM a past it can hold a grudge about. Two halves:

**a) Write memory (the press file).** After each Saturday and Sunday run, the
harness appends that GM's public output to `teams/<slug>/press/2026-wNN.md`:
its `note_reply`, its logged claim/trade/lineup reasoning (verbatim, as
already quoted into the logs), and the outcome line once known ("won the bid
at $23", "lineup fell back — Hall of Shame"). PLAN §3 already defines
`press/`; no command writes it today. This makes each team's folder the
GM's public paper trail. **§8**: add `teams/*/press/` to the contracts.

**b) Read memory (the dossier).** A small pure deriver —
`scripts/gm_dossier.py`, shape `build_dossier(slug, weeks_back=3) -> dict` —
assembles per-team context the Saturday/Sunday commands inject:
- the last 3 owner notes **and the GM's own replies to them** (the feud thread),
- the team's own slice of `state/transactions.jsonl` (last ~10 entries, with
  reasoning — so it remembers what it did and why),
- every line of the last recap that mentions this team by name (grudge fuel:
  the commissioner mocked you, and now you know),
- record trajectory (last 3 results + current standing).

Keep it a *dossier*, not a dump — bounded, curated, cheap in tokens. Isolation
holds: everything in it is that team's own output or public record, never
another GM file. **Dispatch:** deriver → builder-haiku (file plumbing over
committed state, pytest with fixture press/notes files); command wiring →
Opus session (Phase 3 prompt engineering).

### R2. Feed Sunday (one-line-per-item edit to sunday.md)

Add to the Sunday subagent context: the dossier from R1 (or minimally: this
week's owner note + the GM's Saturday `note_reply` + last week's box score +
current standings). No new code — this is a command-prompt edit, Opus
session. This single change is the highest personality-per-effort ratio in
the repo: it turns Sunday from a projection exercise into a reaction.

### R3. Public roster board (unblocks trades)

New derived file `state/league-board.json` — all 12 teams' rosters resolved to
`{team_slug: {starters: {slot: {id, name, pos, nfl_team, proj_pts}}, bench:
[...], ir: [...], faab_remaining}}`. Rosters and FAAB are public record (only
GM *files* are secret), so this breaks no isolation. Include it in the
Saturday context so a GM can actually scout a trade target's roster and name
real players in `trade_offer.in` — today it cannot, which is why the trade
mechanic is decorative. Build it in `scripts/free_agents.py`'s style: pure
`derive_league_board(rosters, players, projections, scoring)` + thin CLI.
**§8** addition, then **dispatch → builder-haiku**.

### R4. Deepen the free-agent pool (make "research" possible)

The pool exists and is correctly derived (see below), but each entry is one
number (`proj_pts`) — thin material for a personality to chew on. Extend
`derive_free_agents` to carry, per player:
- `status` / `injury` (already sitting in `state/players.json`, currently
  dropped on the floor) — enables injury-superstition and "buy the dip" biases,
- a compact `proj` detail: the handful of raw projection keys that matter by
  position (e.g. `rec`, `rush_att`-style volume keys as present in the
  Sleeper rows) — enables "volume guy" vs "touchdown-dependent" takes,
- `last_wk_pts`: actual points from the prior week's `stats.json` when it
  exists — enables overreaction, the most human bias of all.

Backward-compatible (adds keys, renames nothing), but **§8** should be
updated in the same change since it specs this file. **Dispatch →
builder-haiku**, pytest over fixture rows.

### R5. Recap awards (anti-convergence incentive)

Add two required lines to recap.md §3's checklist: **"Most In-Character Move
of the Week"** (named in PLAN §10 as the convergence mitigation, currently
absent) and its inverse, **"Least In-Character Move"** — the GM who quietly
started the highest projection at every slot gets called out for being boring.
Publicly scoring blandness is what keeps ten agents from collapsing into one
optimizer. Command-prompt edit, Opus session, no code.

### R6. Trash-talk forum (the league's shared memory)

Today every channel is private or one-directional (`note_reply` GM→owner,
reasoning GM→log, recap commissioner→everyone) and **no GM ever sees another
GM's words**. Isolation protects GM *files*; public statements are public
record — GM-to-GM interaction is legal under the existing rules, just never
wired. R1 gives each GM a private past; the forum gives the league a shared
one. Feuds need both.

Design — a structured weekly thread, not an open chat:

- **One file per week:** `state/forum/2026-wNN.jsonl`, append-only, one post
  per entry (`{timestamp, team, post}`). At most one post per GM per run:
  appended during Saturday (post-claims swagger) and optionally after
  `/recap` (Monday reactions and excuses). Humans post by typing, through the
  same pipeline.
- **Structured output, existing pipeline:** an optional `forum_post` string
  field on `docs/schemas/saturday-decision.json` (and a matching optional
  post in the recap-reaction step). Parsed by `decisions.py` like everything
  else; quoted verbatim, because the GM's own words are the entertainment.
- **Read side rides the R1 dossier:** every GM's context includes last
  week's full thread plus a highlighted subset — posts that mention its team
  by name, and anything its *next opponent* said. A Sunday lineup
  justification written after the opponent talked trash is exactly the
  content this league exists to produce.
- **Personality-governed, not mandatory:** the GM template's
  Reaction-to-Ownership section extends to a forum policy line — some GMs
  post only after wins, some go silent when losing (itself funny), some
  answer every slight. Optional posting is the defense against ten agents
  emitting generic smack on schedule.
- **No moderation:** the commissioner blocks transactions, never speech. The
  recap instead gets a **"Quote of the Week"** line — the incentive to bring
  material rather than volume.

Cost control: context is bounded to *last week's thread only* (~12 posts
max), so token growth is negligible. **§8**: `state/forum/` is a new state
file and `forum_post` a schema change — it MUST ride the same single
contract commit as R1a/R3/R4, not a fourth contract edit. **Dispatch:**
schema + contract → Opus session + human; the append/read plumbing (tiny,
deterministic) → builder-haiku; the command wiring and dossier highlighting →
Opus session (Phase 3 prompt engineering).

### R7. Gut, news, and beliefs (decisions built off more than football)

Owner directive: GMs should decide the way real people do — the goal is to
win, but gut feel, surface-level news, and personal beliefs must factor in.
Three mechanisms, cheapest first:

**a) Demote projections in the run prompts (free, highest leverage).**
Today's prompts implicitly hand agents projections as the answer key; reframe
them as *"the analytics department's opinion"* — evidence the GM may trust,
discount, or resent according to its philosophy. Enforce **beliefs-first
ordering** in the Saturday/Sunday subagent instructions: the agent must state
its in-character read of the week FIRST (reacting to the news digest, the
owner note, the forum, last week's wound), then choose moves consistent with
that read. "You are trying to win — the way YOU believe games are won." If
the prompt says maximize projected points, personality dies regardless of the
GM file. Opus-session command edit, no code.

**b) Template: add "Gut & Superstitions" + "Media Diet & Gullibility"
sections.** Gut must fire on *triggers*, not sit as flavor: 3–5 hard rules
per GM with bounded magnitudes ("never start a player against his former
team"; "a two-TD game buys three weeks of blind trust"; "won't bid on players
from the team that eliminated him"). Design rule: every gut trigger must be
capable of LOSING the GM points — a bias that always aligns with projections
is decoration. Media Diet says which news this GM overreacts to, which it
ignores, and whether it believes rumors. Template edit (Opus session);
content lands with Phase 5 GM writing.

**c) The news feed: `state/news/2026-wNN.md`, two tiers.**
- **Derived headlines** — deterministic, zero new deps: a small
  `scripts/derive_news.py` turns week-over-week deltas the repo already syncs
  into storylines — injury-status changes (`players.json` diff), last week's
  biggest over/under-performers vs projection (`stats.json` −
  `projections.json`), blowout margins (`matchups.json`), and the week's
  biggest FAAB bids (`transactions.jsonl`). That's a real media cycle
  generated from committed state.
- **Planted storylines** — humans and the commissioner (in voice) may append
  real-world headlines or outright rumors to the digest. Rumors need not be
  true; each GM reacts per its Media Diet line. The owners become the
  tabloid press, which is the point.
The digest joins the Saturday/Sunday context via the R1 dossier. Live
external news feeds are deliberately OUT: they'd break the Sleeper-only,
read-only data layer, and derived + planted covers the effect.

Competitive floor: no "irrationality budget" needed — validators, FAAB caps,
the fallback lineup, and the magnitude bounds written into each bias already
keep gut from breaking the league; the recap punishes the rest. **§8**:
`state/news/` is a new state file — add it to the contract update (or a
follow-up §8 edit if that commit has landed). **Dispatch:** derive_news.py →
builder-haiku (pure diff-to-headlines, pytest over fixture weeks); prompt +
template edits → Opus session.

### R8. The media mogul: Kris Jenner runs the tabloid, NOT the league

Owner question: should the commissioner itself become a personality (Kris
Jenner)? Recommendation: **no to re-casting the commissioner, yes to hiring
her** — as a second voice agent with total editorial control and zero powers.

Why not the commissioner's chair: its neutrality is load-bearing — it
validates transactions, resolves FAAB ties, and holds the league's only
judgment power (the collusion veto). Kris Jenner's comedic engine is
scheming favoritism, which is exactly the trait the referee cannot carry: an
agent playing her faithfully bends rulings for storyline; an agent playing
her fairly is a defanged parody. The existing funereal voice
(agents/commissioner.md — "the transaction was, regrettably, legal") is also
the league's best deadpan foil and should not be lost.

Instead: **`agents/media.md`** — the league's media mogul, publisher of the
R7c weekly digest:

- **She writes `state/news/2026-wNN.md`.** Inputs: derive_news.py's
  deterministic headlines + the owners' planted rumors. Output: the digest in
  her voice — hyping favorites, burying teams that bore her, momaging feuds
  into existence, taking credit for breakouts ("I made that waiver claim
  happen, sweetie").
- **Mechanical biases, per house style (affectionate parody):** favors teams
  that generate drama (forum posters, big bidders, note-spiters); punishes
  boring efficiency with silence; frames every lopsided trade as a
  masterstroke by whoever she is currently promoting; periodically
  manufactures a rumor about one team purely to see what its GM does with it.
- **Access: public record ONLY** — rosters, transactions, forum, recaps,
  standings. She never reads GM files (that stays commissioner-only). This
  is a feature: her speculation about GM *motives* is funnier when she
  cannot actually know them, and isolation stays intact.
- **The running bit:** her tabloid drops before the Saturday run, the GMs
  react through their R7b media-diet lenses all week, and the commissioner's
  Monday recap wearily corrects the record ("contrary to reporting, no trade
  demand was ever filed"). Referee vs tabloid is a permanent two-voice
  engine at zero marginal cost — she authors a context file the GMs already
  receive under R7c.

Structural cost is one agent file plus one line in /saturday (spawn the
media agent to publish the digest before the GM subagents run). No new
powers, no new state beyond R7c's `state/news/`, no §8 change beyond it.
**Dispatch:** agents/media.md + command wiring → Opus session + human
(Phase 3/5 content — voice is the product); nothing to send to builders
beyond R7c's derive_news.py, which is unchanged.

### R9. Surface the show in the artifact: Feed tab + League Guide tab

Two new tabs:

**a) "The Feed" — the league's media ecosystem, one tab.** Rendered per
week with the same ‹ › week stepper as Scores, three stacked sections:
1. **The tabloid** — that week's `state/news/<season>-wNN.md` (Kris's
   digest), rendered as the front page it is.
2. **The forum thread** — `state/forum/<season>-wNN.jsonl` (shape already
   live: `{timestamp, team, post}` via `scripts/forum.py`), newest first,
   each post attributed with the team's display name.
3. **The commissioner's recap** — `state/weeks/<...>/recap.md` once the
   week is official.
Reading order on the page = the week's story arc: tabloid stirs it, GMs
talk, commissioner buries it. `build_viewer.py` grows three loaders (all
committed state, no network) and the injected data blob grows a `feed`
key per week. Escape all post/markdown text — GM output is untrusted
content in an HTML page. **Dispatch: builder-haiku** (file plumbing +
templating; pytest over fixture forum/news/recap files, in the style of
test_build_viewer.py).

**b) "League Guide" — the standing explainer page.** A mostly-static tab
assembled by `build_viewer.py` from committed sources so it can never drift
from reality:
1. **What this is** — the mission paragraph (source: README).
2. **The cast** — all 12 teams: display name, human or AI, current record
   (from standings), and a 1–2 sentence public persona blurb. GM files are
   agent-private, so blurbs come from a new **"Public bio"** line added to
   the GM template (and to each Phase 5 GM file) — the persona is public,
   the mechanical strategy stays out of the artifact. Include the
   commissioner and the media mogul as cast entries — the league has 14
   characters, not 12.
3. **The rules** — rendered from `config/league-rules.md` verbatim (it is
   already the canonical short rulebook; do not restate it by hand).
4. **How the league runs** — the weekly rhythm as a command-line walkthrough:
   `/notes` (Fri) → `/saturday` (waivers/trades) → `/sunday` (lineups) →
   `/recap` (Mon official) → `/loop 10m /refresh-board` on game days, one
   commit per run, git history as the league's permanent record. Source the
   descriptions from the commands' own frontmatter `description` lines so
   the guide stays true as commands evolve.
**Dispatch:** template + loaders → builder-haiku; the "Public bio" template
line + guide copy tone pass → Opus session + human (content). No new state
files, no §8 change — every source is already committed and contracted.

Note for the artifact publish step (/refresh-board): the viewer is shared
league-wide, so The Feed makes forum posts and the tabloid visible to
everyone with the link — that is the point, but it means owner-planted
rumors are public the moment they print. Plant accordingly.

### R10. The GMs' Meeting: seeded opinions of the rest of the cast

Owner directive: once the agents are created, each GM needs an initial
working opinion of every other GM — including the media mogul — formed the
way real people form them: from reputation, public persona, and any
real-world history between these celebrities. Week 1 should feel like a
season already in progress, not twelve strangers shaking hands.

**The ceremony: a one-time preseason run, `/gms-meeting`.** After Phase 5 GM
files are written and before the draft:

1. For each AI GM, spawn one isolated subagent with ONLY its own
   `general-manager.md` plus the **public cast sheet** — the 13 other
   characters' names and Public bio lines (the 11 other GMs, the
   commissioner, the media mogul). Isolation holds: opinions are formed
   from who these people publicly *are*, never from another GM file.
2. The agent draws on its own knowledge of the real celebrities' public
   personas and any real-world history between them (feuds, friendships,
   collaborations, awards-show incidents) — affectionate parody,
   public-record-level only, same house rule as the GM files themselves.
3. Output: `teams/<slug>/opinions.json`, validated against a new
   `docs/schemas/gm-opinions.json`. Per counterpart:
   - `stance` (enum: respect / rival / dismissive / wary / soft-spot /
     unknown),
   - `take` — one in-character sentence (quotable; these will surface in
     forum posts and trade messages all season),
   - **at least one mechanical hook** — the template rule applies to
     relationships too: "will never accept the first offer from X,"
     "believes everything the tabloid prints about Y," "checks Z's forum
     post before setting a lineup." A vibe without a mechanic is decoration.
   - Required entries for the **media mogul** (their media diet gets a
     Kris-specific line: does this GM court her, fear her, or refuse to
     read her?) and the **commissioner** (respect it, resent it, test it).
4. **Kris holds the meeting too:** one media-agent run producing her
   coverage priors on all 12 GMs — who starts as a Golden Child candidate,
   who she's already decided is boring — folded into her week-1 issue as a
   "Season Preview" front page. The commissioner needs no opinions file; it
   has already seen everything and expects the worst uniformly.

**How opinions flow into the season:** each team's `opinions.json` joins its
own R1 dossier context (Saturday/Sunday/trade responses) as its *priors* —
the GM's lived experience (press, forum, transactions) then layers on top,
so a preseason rival can become a grudging ally through actual events
without editing any file. The opinions file is agent-private in context
terms (only its own GM and the commissioner ever load it) but sits in the
repo like everything else — the humans can read the whole matrix, which is
half the fun. Keep it OUT of the artifact (R9's Guide shows public bios,
not private opinions); consider a season-end "declassified" reveal in the
final recap.

**Revision rule:** opinions.json is rewritable under the same governance as
GM files — max 3 edits per season, note windows only, logged in
`state/rulings.md` — so a mid-season falling-out can be formalized but not
churned weekly.

**§8**: `teams/*/opinions.json` is a new state file + one new schema —
needs the follow-up contract edit (can ride with `state/news/`).
**Dispatch:** schema → builder-sonnet or Opus (it gates agent output);
`/gms-meeting` command + cast-sheet assembly → Opus session + human (it's
Phase 3-style prompt engineering and the output quality IS the product);
dossier wiring → one-line addition to gm_dossier.py (haiku).

### Sequencing

R1a/R3/R4/R6/R7c contract edits land together as one §8 update (human
sign-off), ideally alongside the Blocker-4 §8 consolidation — one contract
commit, not six. Then R1b/R3/R4/R6-plumbing/derive_news dispatch to
builder-haiku in a single batch (ROUTING rule 1), and R2/R5/R7a plus the R6
command wiring are same-day Opus command edits. R7b's template sections land
with them, and R8's agents/media.md is written alongside the Phase 5 GM
files (same voice-first content pass). All of it lands before Phase 5 GM
writing, so the GM files can be written *against* the context they'll
actually receive — including each GM's forum voice, posting policy, gut
triggers, and media diet.

R9 (viewer tabs) slots after the R6/R7c state files exist — The Feed
renders forum + news + recap, so it can ship with placeholder-empty weeks
any time, but is only worth eyeballing once at least one week of forum and
tabloid content is committed. The League Guide's cast section needs the
Phase 5 "Public bio" lines to be complete, but the tab itself (mission,
rules, command walkthrough) can build immediately and show the cast as
"signing in progress" until then.

R10 (the GMs' Meeting) is the last preseason step before the draft: it
requires every Phase 5 GM file + Public bio to exist, and the draft should
run AFTER it so opinions are live from pick one (a GM sniping a player it
knows a rival wants is draft-day content). Preseason order: Phase 5 content
→ `/gms-meeting` → mock draft → real draft.
